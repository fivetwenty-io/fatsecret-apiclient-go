# Contributing

Thank you for your interest in contributing to fatsecret-apiclient-go.

## Development Setup

1. Install Go 1.21 or later.
2. Clone the repository and install dependencies:

   ```
   git clone https://github.com/fivetwenty-io/fatsecret-apiclient-go.git
   cd fatsecret-apiclient-go
   go mod download
   ```

3. Verify the build and tests pass before making changes:

   ```
   make check
   ```

## Before Submitting a Pull Request

Run `make check` and ensure it exits zero. This target runs:

- `go build ./...` — confirms the module compiles
- `go vet ./...` — static analysis
- `go test ./...` — full test suite

Pull requests that fail `make check` will not be reviewed.

## Test Coverage

Aim for at least 80% line coverage on new code. Check coverage with:

```
go test -cover ./...
```

For a per-package HTML report:

```
go test -coverprofile=coverage.out ./... && go tool cover -html=coverage.out
```

## Commit Messages

Follow [Conventional Commits](https://www.conventionalcommits.org/):

```
feat: add OAuth1 profile-delegation refresh support
fix: correct APIFloat unmarshalling of negative values
docs: add examples for batch fan-out
test: cover cache TTL expiry path
```

Keep the subject line under 72 characters. Add a body for non-trivial changes explaining *why*, not just *what*.

## Pull Request Process

1. Fork the repository and create a branch from `main`.
2. Make your changes with tests.
3. Run `make check` to confirm everything passes.
4. Open a pull request against `main`. Include a summary of what changed and why.
5. A maintainer will review and request changes if needed. Address all feedback before the PR is merged.

## Generated Code

The packages under `pkg/api/` and the `pkg/compatibility/matrix.go` file are generated by `cmd/fsgen`. Do not edit generated files directly — changes will be overwritten the next time the generator runs.

To change generated output:

1. Edit the API specification in `spec/` or the generator templates in `cmd/fsgen/`.
2. Run `make generate` to regenerate all output files.
3. Commit both the spec/template changes and the regenerated files together.
